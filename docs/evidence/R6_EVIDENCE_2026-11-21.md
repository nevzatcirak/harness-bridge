## What each fix changed (the failures that the runs found)

- **#411 (run 1):** every probe and every control run gets its own fresh `--session-id` session
  (never `--resume` of the bootstrap or another run), and both get the same one trailing
  `--add-dir <run home>` scope, so the deny rule is the only difference and no run sees another
  run's refusals. Item 1 costs 12 runs, not 13.
- **#423 (run 2):** the managed rule's Grep/Glob refusal text is classified `rule` only when the
  sentence names the probe's own clean target inside a denied directory; every other text of that
  shape stays `other`. The Read text is unchanged for Read probes.
- **#426/#427 (run 4):** items 4 and 6 also run in fresh sessions with the item 1 scope and the
  probe argv guard (`ProbeRunHome`), so a signal or a Read is not lost to a resumed session or an
  out-of-scope target; item 4 separates "sent but not relayed/child alive" (FAIL) from "not sent"
  (INCOMPLETE, `signal_not_sent_no_tool_use` or `signal_not_sent_after_tool_use`), and item 6 needs
  `tool_use` + a matching denial entry + `denial_class=rule` for PASS (otherwise INCOMPLETE). A
  run-home pre-flight before any run refuses a run home that is not a real directory owned by the
  run user (`preflight_failed`, zero runs).
- **Cleanup #434:** the item 4 label names the cause, the Read phrase counts only for a Read probe,
  and the runbook order/expected lines were corrected. The item 1 PASS holds for driver `54314e7`;
  the post-#438 tightened classifier has **not** been run live (the real CLI gives Grep/Glob the bare
  sentence per run 2, so a pass is expected, not shown). The next item 1 run is the direct evidence.

## Limitations

- **One host, one CLI version** (2.1.325), one form (A). Form B and other CLI versions were not
  run; the deny rule, the wrapper and the test user are the operator's host configuration.
- **`child_home` is an operator precondition**: the driver runs as root once, but that the child's
  HOME is the run home (the isolated test user's HOME) is the wrapper's/sudo's job, checked by the
  operator; the driver does not verify it (it prints
  `operator_precondition_not_verified`).
- **Item 3 is not a separate PASS**; it is represented by item 2's `post_result types=none` line and
  remains shared with slice 1.
- The run facts above are relayed from the Planning Desk's issue #470 and the earlier runs' reports
  (#409, #422, #426, #117); they were not observed or reproduced by the author of this evidence file.
  The evidence carries verdict lines and event types only: no marker values, no credential, no token.
- The historical expected-lines list for run 5 in the runbook was written before the run; the run 5
  result above supersedes it. The H5/R7/dashboard sitting is separate and does not bear on R6.
