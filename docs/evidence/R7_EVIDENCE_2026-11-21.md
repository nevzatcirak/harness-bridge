## First attempts: FORBIDDEN because of the host (findings F-H5-1, F-H5-2, F-H5-3)
The first creates were refused `FORBIDDEN` (no reason given) and the first overlay start failed, all from host
permissions, not from the Bridge's policy:
- the test workspace was owned by the agent user, which a lifecycle root may not be (owned by root or the service user): fixed by changing the owner to root with the agent's group, mode `0710`, and an ACL (`u:<agent-user>:rwx`) for the agent;
- the service user could only search the root (`--x`): `os.OpenRoot` needs read permission, so every create was refused without a reason until the service user got `r-x` on the root and on the created directory, and read on its `.git`;
- the overlay directory made by hand under `/var/lib` failed with `openat overlay.lock: read-only file system` under the unit's `ProtectSystem`: fixed with a `StateDirectory=` (mode `0700`).

The Bridge now refuses to start for the second case and says `unavailable` for a create refused by a failed
filesystem check (code, task #460); the runbooks carry all three.
